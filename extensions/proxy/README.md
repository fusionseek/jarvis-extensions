# 代理

用你自己装的 [sing-box](https://sing-box.sagernet.org) 跑你的订阅。菜单栏一枚图标随手开关、换模式、切节点与策略组，
开着时把这台 Mac 的系统代理指向它，或者打开**增强模式（TUN）**让整机网络都经过它；能导入你的 **Surge 配置**里的规则，
给正在看的网页一键加「走代理 / 直连 / 拒绝」，悬浮球上看**有效流量与成败**。工具箱里一页看状态与节点，工作区窗口里看连接、规则、日志与订阅。

它**不自带内核**：sing-box 是你用 Homebrew 装的那一份（没装时可以一键在终端里装）。扩展做的是订阅解析、
生成 sing-box 配置、经 sing-box 自己的控制口（Clash API）切节点与测速，以及三处界面。

> 需要 Jarvis **3.2.7** 及以上：菜单栏域、常驻进程、系统代理、「按你填的地址联网」，以及增强模式（网络助手）、悬浮球那一层、
> 读浏览器当前页、挑文件、常驻进程重载，都是这一版宿主开始提供的（jarvis-mac `specs/20261028-111714-proxy-tun-orb-traffic-page-rules`）。
> `minimumJarvisVersion` 里的 3.2.7 是给下一次宿主发布占的号，宿主那一版的版本号定下来之后跟着改。

## 入驻哪里

| 位置 | 是什么 |
| --- | --- |
| 菜单栏 | 一枚自己的图标：开着 `network`、增强模式开着 `network.badge.shield.half.filled`、关着 `network.slash`、出错 `exclamationmark.triangle`。仿 Surge 的菜单：顶部一块流量曲线、状态、开关、设为系统代理（勾）、增强模式（TUN，勾）、出站模式、策略组（「节点选择」与导入的每一个组）、当前页面（地址栏的网站与它拉的别家域名 › 走代理 / 直连 / 拒绝 / 走某个组）、最近请求（失败的画红 › 加规则）、测速、更新订阅与规则集、重新载入配置、导入 Surge 配置、规则、复制终端代理命令；末尾「打开」「设置」两项是 Jarvis 固定加的。「菜单栏显示速率」打开时图标旁两行速率（每行固定 4 个字符） |

| 工具箱「代理」 | 状态与总开关、设为系统代理、增强模式、最近一分钟的流量曲线（与菜单顶部那块同一种画法）、有效速率与成败、模式（规则 / 全局 / 直连）、节点列表（点选即切、测速）、策略组、规则、订阅、终端代理命令；卡住时一张说明卡写清楚还剩哪几条路 |

| 设置 · 扩展 · 代理 | 订阅地址与下面那张表里的偏好 |

## 要哪些授权，为什么

九项。第一次打开「代理」时 Jarvis 弹一次授权屏一次问完，之后可以在 `设置 · 扩展` 里逐项撤销。

| 能力 | 拿来做什么 | 宿主替你拦住的 |
| --- | --- | --- |
| `process.daemon`（高风险） | 在后台常驻运行 `sing-box run -c ‹配置文件› -D ‹工作目录›`，并经它的本机控制口切节点、测速、读流量 | 只能跑 manifest 里逐字写的这一条命令，扩展能决定的只有配置文件的内容；以你的身份运行、不经 shell；控制口只发往 `127.0.0.1` 上它自己报的端口 |
| `system.proxy`（高风险） | 开着时把系统代理指向 `127.0.0.1:‹本地端口›`，关掉时还原 | 只能指向本机、只能在 sing-box 跑着的时候设；sing-box 死了、扩展停用 / 卸载、Jarvis 退出或崩溃之后，Jarvis 自己还原，扩展拦不住 |
| `network.tunnel`（高风险） | 增强模式：以管理员身份运行 sing-box 接管整机网络，命令行工具与不认系统代理的应用也走它 | 第一次打开时要你输一次管理员密码，装上 Jarvis 的网络助手；跑的是那一刻拷进 root 目录、校验过哈希的 sing-box 副本；配置过 Jarvis 的守卫（不许有任何文件路径、只监听本机），TUN 段由 Jarvis 填；Jarvis 退出或崩溃时内核立刻停；卸载网络助手在 设置 · 扩展 · 代理 |
| `network.https`（高风险） | 拉取你在设置里填的订阅地址与规则集地址 | 只放行你此刻填着的那几条地址的主机（删掉一条，下一次就拦），只走 HTTPS |
| `terminal.run`（高风险） | 没装 sing-box 时在终端里替你装（装过就升级） | 只能按 id 点名 manifest 里那段脚本，脚本全文在 `extension.json` 里 |
| `notifications.post` | sing-box 意外退出、`/proxy` 开关的结果用横幅告诉你 | — |
| `clipboard.write` | 菜单栏「复制终端代理命令」 | 只写不读 |
| `browser.activeTab` | 菜单栏「当前页面」：读前台浏览器当前标签的地址，给这个网站加规则 | 只读当前标签的地址与标题；每个浏览器第一次读时 macOS 还会问一次「自动化」；地址不出本机、不写进存储 |
| `files.pick` | 导入 Surge 配置时让你挑那份 `.conf` | 只拿到你挑的那一份的文件名与正文，拿不到路径 |

**sing-box 继承 Jarvis 的全部系统权限，包括完全磁盘访问。** 授权之前请确认你信任自己装的那一份 sing-box。
不给 `process.daemon` 它什么都做不了；其余几项可以只给一部分：不给 `system.proxy` 就只在本机端口上可用，
不给 `network.https` 就不能更新订阅，不给 `terminal.run`「代理」页面里就没有安装按钮（设置里 sing-box 那一行的「在终端中安装」是你亲手点的，跑的是同一段脚本，照样可用；或者自己 `brew install sing-box`），不给 `network.tunnel` 就只有系统代理模式。

## 会运行、读取、写下什么

- **运行**：`sing-box run -c ‹配置文件› -D ‹工作目录›`。配置文件由 Jarvis 写到 `~/Library/Application Support/Jarvis/extension-runtime/proxy/sing-box/config.json`（0600），停止后删掉；
  sing-box 自己的 `cache.db`（选中的节点、模式、下载过的规则集）留在同一个目录里，卸载扩展时整个删掉。
- **联网**：只请求你填的订阅地址（User-Agent 带 `sing-box`，机场据此回本扩展认得的格式）。sing-box 开着时，
  第一次会从 `testingcf.jsdelivr.net` **直连**下载两份中国大陆规则集（`geosite-cn`、`geoip-cn`），之后存在 `cache.db` 里每天更新一次。
- **增强模式**：sing-box 由 Jarvis 的网络助手以 root 运行，配置与它的缓存在 `/Library/Application Support/Jarvis Tunnel/run/`（root 所有），不在你的用户目录里。
- **存储**（扩展自己的键值存储）：解析出的节点、每条订阅的结果（主机名、节点数、认不出的行、用量）、选中的模式、节点、增强模式与策略组、测速结果、
  控制口的随机 secret、页面规则、导入的 Surge 配置（转换后的规则、策略组、TUN 相关的几项；**不含** `[Proxy]`、`[MITM]`、`[Script]` 的任何内容）与拉下来的外部规则集。
  **订阅地址本身不进存储**：它在钥匙串里（订阅地址里的 token 就是密码），存储里只放它的散列与主机名。

## 怎么用

1. 装上「代理」，打开它，批准授权屏。
2. 没装 sing-box 时点「在终端中安装」：有 Homebrew 就 `brew install sing-box`（装过就 `brew upgrade sing-box`）；没有 Homebrew，终端里写明还剩哪几条路。装好之后页面自己会换掉那张卡。
3. 在 `设置 · 扩展 · 代理` 里填订阅地址（可以几条），回来点「更新订阅」。
4. 打开总开关（或菜单栏「开启代理」、或 `/proxy`）。默认规则模式：局域网与中国大陆直连，其余走「节点选择」。
5. 命令行工具不读系统代理：点「复制终端代理命令」，在终端里粘贴那一行 `export https_proxy=… http_proxy=… all_proxy=socks5://…`；或者打开增强模式，它们就都走代理了。

### 增强模式（TUN）

菜单栏、工具箱或设置页里拨「增强模式（TUN）」——三处是同一项偏好，哪边拨了另外两处跟着变。第一次打开时 macOS 弹管理员密码框——那是装 Jarvis 的网络助手（一个 LaunchDaemon），之后开关不再要密码；
`brew upgrade sing-box` 之后的第一次再要一次，把新版拷进去。开着时整机网络经过 sing-box：DNS 由它答（默认 fake-ip，与 Surge 增强模式相同），
局域网、`100.64/10` 与你导入的 `tun-excluded-routes` / `bypass-tun` 不进 TUN；系统代理照样设（认系统代理的应用少绕一次）。
Surge 的增强模式或别的 VPN 开着时它不会启动，会写明是谁占着。

### 端口

本地端口（7890）与控制端口（19090）被**「代理」自己**占着时（上一次的内核还没退完、上一个 Jarvis 留下的 sing-box），它先停掉自己的内核、再起一次，
不让你去换端口；Jarvis 启动时也会先等上一次留下的 sing-box 真的退出再开。第二次还冲突，才是真的被别的程序占着，照常告诉你是哪个端口。

### 导入 Surge 配置

窗口「规则」页（或菜单栏「导入 Surge 配置」）挑一份 Surge 的 `.conf`：`[Rule]` 里的 DOMAIN / DOMAIN-SUFFIX / DOMAIN-KEYWORD / IP-CIDR(6) / GEOIP / PROCESS-NAME /
逻辑规则 / RULE-SET / DOMAIN-SET / FINAL、`[Proxy Group]` 的策略组、`[General]` 里 TUN 相关的几项、`[Host]` 转成 sing-box；USER-AGENT、URL-REGEX、URL Rewrite、MITM、Script
转不了，报告里逐类列出。节点仍然来自订阅：Surge 配置里的节点名一律落到「节点选择」上。
`RULE-SET` 的地址要联网拉，而它们来自你挑的文件——Jarvis 只放行你亲手填进设置的地址，所以报告里有「复制这些地址」，贴进 `设置 · 扩展 · 代理 · 规则集地址`（一次贴多行会拆成多条）之后才去拉。

### 当前页面与页面规则

在浏览器里看着一页时点开菜单栏图标，「当前页面」列出地址栏的网站与这个浏览器最近 30 秒连过的别家域名（页面拉的 CDN、接口），按可注册域名归并；
选「走代理 / 直连 / 拒绝」或导入的某个组，就加一条规则（含全部子域名），排在所有规则之前，立刻重新载入——不断开连接、不动系统代理。
「最近请求」与窗口「连接」页里的每一条也能这样加。页面规则都在窗口「规则」页里，可以改、可以删。

### 悬浮球上的流量

一条连接拿到对端的回包算**成功**；拨号失败、解析失败、超时、被重置、被规则拒绝、一个回包都没收到的算**失败**。外圈是最近 10 秒里判定了的连接的成败比例；
球心的速率只算成功连接上的字节——一个连不上的节点不会让球上显示「有流量」。

## 它怎么做的

- **订阅**：认 `ss://`（SIP002 与旧式整段 base64）、`vmess://`（v2rayN 的 base64 JSON）、`vless://`（含 `security=reality`、`flow=xtls-rprx-vision`、ws / gRPC / HTTP / HTTPUpgrade）、
  `trojan://`、`hysteria2://` / `hy2://`（含端口跳跃与 salamander 混淆）、`tuic://`（v5），以及 sing-box 自己的 `{ "outbounds": [...] }`。
  认不出的行逐条记下原因（订阅页能看到），不中断整份；sing-box 会拒绝的写法（REALITY 公钥不对、UUID 不合法、不支持的加密……）在解析时就挡下，
  因为一个坏节点就会让整份配置起不来。两条订阅里重名的节点依次加「 2」「 3」。一条订阅拉失败时保留它上一次的节点。
- **配置**：`mixed` 入站（`127.0.0.1:‹本地端口›`）；每个节点一个出站；「节点选择」（自动选择 + 全部节点，手动切换时断开旧连接）、「自动选择」（按延迟）、导入的策略组；
  规则依次是嗅探 →（增强模式）DNS 劫持 → 私有地址与 `.local` 直连 → 直连 / 全局模式 → 页面规则 → 导入的 Surge 规则（没有时：中国大陆域名与 IP 直连）→ 其余走 `FINAL` 或「节点选择」。
  系统代理模式下 DNS 只用系统解析器（走代理的域名由远端解析）；增强模式下直连解析用 UDP 直接问 `dns-server`、代理侧用经「节点选择」的 DoH、默认给 fake-ip。
  导入的 IP 规则沿用 Surge 的语义：第一条不带 `no-resolve` 的 IP 规则之前插一条 `resolve`。
  每一份配置都对过 sing-box 1.14 文档与源码，并在本机 `sing-box check` 上验过（见 `test/singbox-config.test.mjs`）。
- **开启**：起 sing-box → 等它的控制口开始答话（规则集在这段时间里下载）→ 把你选的模式与节点放回去（`cache.db` 会记着上一次的，启动时以它为准）→ 设系统代理。
  规则集第一次下载失败时不分流再起一次，页面上写明「这一次没有分流」。
- **被别的代理工具拦着**（Surge 增强模式、别的 VPN）：系统代理写了也不生效，所以 Jarvis 不写；sing-box 照常跑在本地端口上，页面写明是谁拦着，并给「复制终端代理命令」。

## 已知边界

- **系统代理模式管不到的**：不读系统代理的程序（多数命令行工具、部分游戏与 IM）与 UDP——打开增强模式就都管得到了。
- **增强模式要网络助手**：它是一个以 root 运行的 LaunchDaemon，装与卸都要管理员密码；`brew upgrade sing-box` 之后第一次打开要再输一次。
- **Surge 配置里转不了的**：USER-AGENT / URL-REGEX 规则、URL Rewrite、MITM、Script、模块——sing-box 不解 HTTPS 正文、不跑脚本；`[Host]` 的通配与别名；`RULE-SET,SYSTEM`。
- **当前页面读 Firefox**：Firefox 没有读地址的 AppleScript，只能看连接表里它连过的域名。Safari 的网络进程是系统共用的 `com.apple.WebKit.Networking`，别的 WebKit 应用的连接也会算进来。
- **Clash YAML 订阅不认**：订阅地址回的是 Clash 配置时，订阅页写明「这是 Clash YAML 格式的订阅」。向机场要分享链接格式（常叫「通用订阅」）的那个地址。
- **`/proxy 开`、`/proxy 关`**：manifest 的 `slash.argument` 一旦声明，`/proxy` 回车就会先补全等你打参数；为了让最常用的「直接切换」一下就跑，这里没声明它。
  Jarvis 把指令后面的字带过来时认「开 / 关」，不带时切换。
- **菜单栏关掉时**：sing-box 意外退出的横幅由菜单栏那一侧的后台会话发。你在设置里关掉「在菜单栏显示」之后，内核死掉时不再有横幅
  （Jarvis 照样还原系统代理，页面开着时照样显示「起不来」那一屏）；「启动 Jarvis 时自动开启」也靠菜单栏图标起来的那一刻。
- **订阅更新会重新载入内核**：节点真的变了且代理开着时，自动更新会让 sing-box 原进程重载一次（SIGHUP），系统代理不动；正在走的连接会断一下（sing-box 重载时会重建出站）。端口改过、换了内核（增强模式开 / 关）时只能重开。
- **REALITY 连不上**：多半是 sing-box 太旧。「起不来」那一屏会给「在终端中更新 sing-box」。
- **Hysteria2 的 `pinSHA256` 不映射**：官方是整张证书的 SHA-256，sing-box 的是公钥的，二者不等价。
- **控制口 secret 用 `Math.random` 生成**：JavaScriptCore 里没有保证可用的 `crypto.getRandomValues`。控制口只听 127.0.0.1，secret 挡的是同机别的程序顺手调它。
