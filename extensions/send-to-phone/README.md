# 发到手机

读一次剪贴板，经 Jarvis 快传把文字或链接推到已配对的手机上。不想开面板时，在全局搜索或速记里敲
`/phone <文字>`，它在后台直接发，结果在 Inbox 里留一条。

## 入驻哪些域

manifest v2（SDK 2）按域声明：

| 域 | 在哪里 |
| --- | --- |
| 工具箱 | 工具箱目录里一行；点开是面板里的那一页（内容、快传状态、发送） |
| 指令 | `/phone <文字>`（也认 `/发到手机`），静默发送 |
| 设置 | 下面「设置」那两项 |

Inbox 只开消息一路（`inbox: { messages: true, notifications: false }`）：发完（或没发出去）投一条 Inbox 消息，不弹系统横幅。

## 它要哪些授权，为什么

| 能力 | 用来 |
| --- | --- |
| 读取剪贴板 | 页面上「读剪贴板」那颗按钮；`/phone` 没跟字时读一次 |
| 查看快传状态 | 知道服务开没开、有没有手机接入；`/phone` 发之前先问一句 |
| 开启 / 停止快传 | 服务没开时页面上那颗「开启快传」按钮；**不会在你没按的情况下打开**——`/phone` 也不会 |
| 经快传发送 | 「发到手机」与 `/phone` |
| Inbox 消息 | 发完留一条「已推到 iPhone」，关掉面板也看得见；`/phone` 没发出去时说清为什么 |

每一项都可以在授权弹窗里单独关掉；关掉的那一项对应的按钮会失效并给你一颗「授权」。

## 怎么用

**在页面里：**

1. 快传 → 开启，手机扫码接入（或在这个扩展里按「开启快传」再去快传面板扫码）。
2. 复制一段文字，进「发到手机」，按「读剪贴板」，按「发到手机」。
3. 手机页面的下行流里出现这条消息；Inbox 里多一条「已推到 …」。

**用 `/phone`：**

- `/phone 在路上看这个 https://…` 回车：直接把那段字推到手机，面板不动。
- `/phone` 后面不跟字：读一次剪贴板发出去。
- 两种都按「去掉首尾空白」偏好处理。
- **快传没开时不替你开**：那是一个对局域网敞开的端口，后台里没有地方问你要不要开。它只在 Inbox 里投一条 warning，
  说快传没开、怎么打开，以及没发出去的是哪一段；开好之后再敲一次。
- 没有要发的字（剪贴板也是空的、或是密码管理器标记的机密内容）、缺授权、宿主发送失败——都各有一条 Inbox 消息说清楚。

## 设置

- **去掉首尾空白**（默认开）：页面与 `/phone` 都按它。
- **发送前确认**（默认关）：开着时页面上的「发到手机」要按两次。`/phone` 不受它管——回车本身就是确认。

## 已知边界

- 只发文字与链接；发文件请用快传面板本身。
- 没有手机接入时照样能发，只是没人收到——与在快传面板里发一样。
- 不做发送历史；快传面板的活动流里有。
- Inbox 10 秒内最多投一次：连着发两条，第二条的回执可能投不出去（发送本身不受影响）。
- `/phone` 跑在 Jarvis 的后台会话，读不到页面编辑框里那段草稿；要发草稿就在页面上按「发到手机」。
- Inbox 消息没有动作按钮（v2 的 `inbox.post` 只有标题、正文、级别）：上一版卡片上的「再发一次」没有了，再发就再敲一次 `/phone`。
- 要 Jarvis 3.0.3 或更新（manifest v2 / SDK 2）：更早的宿主只认 v1 的 manifest，装不上这一版。

## 开发

```bash
npm run build          # → dist/extension.js（提交进仓库）
npm run check          # tsc --noEmit
npm test               # 对着 dist/extension.js 跑 test/*.test.mjs（宿主替身）
npm run validate       # schema + 跨字段规则 + 产物
```
