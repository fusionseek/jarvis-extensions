# 工具箱域、窗口域与扩展商店

## Overview

用户与扩展打交道的入口有三类：工具箱目录里**多出来的行**（工具箱域）、工作区窗口里**一枚扩展标签**（窗口域）、
以及点工具箱末尾那枚虚化的加号进去的**扩展商店**。前两者是扩展入驻的地方，后者是装它的地方。
指令域与服务域的入口不在这里：前者在 `/` 下拉与全局快捷键（[06](06-capabilities.md)），后者在它扩展的那个内置能力里
（[10](10-settings.md)）。

设计源：Figma `hZeo5Kw9MxiE48AiOeRz1H` 页面 `9:78`（`jarvis-extension-store` `1001:2`），每张面板帧恒为 400×520。

## Concepts

### 工具箱目录：内置 · 扩展 · 加号

```text
调色板 / 粘贴板 / Base64 / … / 清理 / 快传        ← 内置，顺序不变
HTTP 状态码 / 发到手机 / 截屏翻译 / …              ← 入驻了工具箱域、且启用着的扩展，按安装先后
＋ 添加扩展                                       ← 虚化的加号，恒在末尾
```

- **只有入驻了工具箱域的扩展在目录里**（`ExtensionCatalogPolicy.items`）。服务扩展没有界面，不该在工具箱里有一行；
  只入驻窗口域的扩展也不在这里。
- 扩展排在内置工具之后、按 `installed_at` 升序：那份内置清单是被人排过的，一行扩展插进中间会让层次读不出来。
- 扩展行 id 是 `extension:<id>`，与内置行隔开命名空间——一个叫 `json` 的扩展不能与内置 JSON 格式化撞成同一行。
- 搜索照常认扩展行（名字 / 说明 / `toolbox.keywords`）；**加号不参与**：它不是一件工具，不进搜索、不进 `↑↓` 序列、
  不进「共 N 个工具」。
- 停用的扩展不在目录里，只留在设置页。

那枚加号的形态（虚线图标井、0.55 不透明度、悬停 1.0）见 `jarvis-mac/docs/uiux/floating-status/design-system.md`。

### 扩展页面（工具箱域）

内容模式 `.extension` + `AppModel.activeExtensionID`。header：徽标 = 26pt 青色方片 + `symbol`，标题 = `name`。
内容区交给渲染器。宿主自己画的几种态扩展碰不到：

| 态 | 屏幕 |
| --- | --- |
| 加载中 | 空白 + 220ms 后才出现的转圈（一次寻常的加载 60–120ms，第 0 帧就转会每次闪一下） |
| 授权未决 | 授权屏（[05](05-permissions.md)），逐条列出声明的能力 |
| 出错 | 一张 `danger` 语义卡 +「重新加载」「去扩展商店」+ 最近 6 条日志 |
| 不兼容 | 「需要 Jarvis ≥ x」/「需要 SDK N」+「检查更新」 |
| 让给了别的扩展 | 「「X」正在用扩展运行时」+「重新打开」——前台会话同一时刻只有一个，不自动抢回 |
| 正开在另一面上 | 「正开在窗口里 · 切到窗口」/「正开在原地结果弹窗里」：同一个扩展同一时刻只画一面 |

面板尺寸门禁照旧：内容装不下时**滚动**（根节点用 `ui.scroll`），面板不长。

### 窗口域：工作区里的扩展标签

`ChromeWorkspaceTab` 多一种内容 `.extension`：按扩展 id 去重（一个扩展至多一枚标签），标题是 `name`、
副标题「扩展 · <window.subtitle>」。标签里画的是**同一个前台会话**的 `window` 那一面，宿主态与面板页面是同一个视图。

| 规则 | 值 | 为什么 |
| --- | --- | --- |
| 正文宽度 | 收在 720pt 以内居中 | 节点树按面板 376pt 的内容宽设计，放宽到将近两倍还读得顺；再宽，`row` 的标题与右侧读数之间隔着半扇窗 |
| 入口 | `presentation: "window"` 的命令、全局搜索里那一行、页面里的 `jarvis.window.open()` | 窗口不是工具箱里的一行；只入驻窗口域、没有工具箱行的扩展才在全局搜索里单列一行（`extension-window:<id>`） |
| 停用 / 卸载 / 不再入驻窗口域 | 标签自己关掉 | 一枚指向已不存在的扩展的标签只会是一页"找不到" |
| 一面优先级 | 弹窗 > 窗口 > 工具箱页面 | 窗口是用户特意开出来的大画布，压过面板里那一页；弹窗是刚按下快捷键要的那一面 |

### 扩展商店

内容模式 `.extensionGallery`，header 标题「扩展商店」。它只读一份本机快照（[02](02-architecture.md)）。

| 元素 | 规则 |
| --- | --- |
| 三档 | 发现（索引里全部）/ 已安装（含索引里已经没有的）/ 可更新（已安装的子集） |
| 搜索 | 认名字、说明、英文名（toolbox / window 的 `keywords`）与 id；空格分词逐词命中；搜索态不分档 |
| 卡片 | 图标井 + 名 + 说明（工具箱的、窗口的、第一个服务的，都没有时取描述）+ 元信息行（版本 · 作者 · N 项能力 · 高风险个数）+ 一颗动作 |
| 徽标 | 一张卡最多一枚：「有更新」压过「新」 |
| 动作 | 未装「安装」；已装「已安装 · 打开」；有新版本「更新到 x.y.z」；装不了时 chip 失效**但不隐藏**，脚注写原因（需要 Jarvis ≥ x / 需要 SDK N / 这一版 Jarvis 读不懂它） |
| 「打开」去哪 | 按域：有工具箱域 → 面板里它那一页；只有窗口域 → 工作区标签；只有服务 → 设置窗口（它的开关在内置区段里） |

**详情**（同一内容模式内的第二屏）：

- 「装上之后 · WHERE IT LIVES」：一行入驻（`工具箱 · 窗口 · 指令 /http · 设置` 或 `服务 · 清理的清理引擎`）；
  入驻工具箱的再画一张「装完会变成这样」的样子行；窗口与服务各一句它出现在哪。
- 命令与快捷键：每条命令一行，`/keyword`、落点徽标（面板 / 窗口 / 原地弹窗 / 静默）、快捷键。
- 它会申请：能力按档位分组；高风险组下面由**宿主**写出会访问的主机，以及受限执行的对象——
  `运行：mo clean、mo --version` / `读取：~/Library/Logs/mole/operations.log` / `终端：安装 Mole（29 行）`，逐字。
- 来源：产物路径 · 大小 · SHA-256 摘要；兼容（SDK、最低 Jarvis、Inbox 通路）；更新时刻、commit、作者。

**安装是一次动作，三步看得见**：从快照取产物 → 校验 manifest 与 SHA-256 → 写入 Application Support。三步都在本机，
安装期间不联网。**不弹授权**：授权发生在第一次进入（或第一次启用它的服务）时，装了没用过的扩展不拿任何能力。

**回执按域说它去了哪儿**：

| 入驻 | 回执 |
| --- | --- |
| 工具箱 | 「已装进工具箱」：目录末尾多了一行「X」 |
| 只有窗口 | 「已装上」：全局搜索里搜「X」在窗口中打开 |
| 指令 | 全局搜索与速记里可以打 `/http`；快捷键已经注册 |
| 服务 | 「已装上 · 在「清理」里启用」：去 设置 · 清理 · 深度清理（Mole）打开它 |

## Usage

1. 工具箱滚到底，点那枚虚化的加号 → 扩展商店。
2. 看卡片；点本体看详情——它入驻哪几处、要哪几项能力、会跑什么命令；点「安装」。
3. 按回执去找它：工具箱那一行 / `/` 指令 / 工作区 / 设置里那个开关。第一次进入（或启用）时授权。
4. 想拿掉：设置 › 扩展 › 该扩展 › 「卸载」或「卸载并删除数据」。

## Gotchas

- 目录里的扩展行**只在启用、且入驻了工具箱域时存在**。
- 「共 N 个工具」包含扩展行、不包含加号。
- 扩展商店与扩展页面属于工具箱主线，header 上工具箱那颗按钮读作「返回工具箱」。
- 窗口标签与面板页面共用一个前台会话：面板里打开另一个扩展，窗口那一枚画「已让给 X」。
